# TJUCPE v2.1 · 学生提交与教师数据工作区

## 1. 角色工作流

### 学生端

学生不再使用实验制图、曲线拟合或数据计算工作区。学生在班级任务中下载教师发布的 Excel 工作簿模板，填写原始实验数据后，将 PDF/DOCX 实验报告与 XLSX/XLS/CSV 数据文件同步提交。学生可查看报告状态、教师反馈和批阅版报告。

学生任务列表只读取任务基本信息。点击某一任务的模板下载按钮时，才读取该任务对应的 `assignment_templates.workbook_snapshot`，不在打开班级页面时批量传输所有模板。

### 教师端

教师创建实验任务后，在“在线 Excel 模板设计”中打开工作簿编辑器，直接编辑单元格、工作表、公式和格式，不需要修改 JSON 或编写代码。教师主动点击保存时，系统才写入该任务的工作簿快照；学生可下载已保存模板。

批阅时，教师在同一页面查看学生报告、PDF 页面和原始 Excel 数据。系统按需读取学生工作簿与教师参考工作簿，支持表格数据比较、工作表/列选择、拟合区间选择、线性/二次/三次拟合与图表预览。图表和拟合在浏览器本地完成，不逐个单元格写入数据库。

## 2. 文件和数据库边界

| 数据 | 存放位置 | 数据库写入方式 |
|---|---|---|
| 学生 PDF/DOCX 报告 | 私有 `lab-reports` Storage | 提交时写报告元数据与文件路径 |
| 学生 XLSX/XLS/CSV 数据 | 私有 `lab-reports` Storage | 与报告在同一提交版本保存文件路径 |
| 教师参考 Excel | 私有 `lab-reports` Storage，路径 `teacher-reference/<class-id>/...` | 只保存文件名、路径、大小、MIME、说明等元信息 |
| 教师任务模板 | `assignment_templates`，每任务一条 JSONB 工作簿快照 | 教师明确点击保存时写入，最大 400 KB |
| 制图、拟合和图表状态 | 浏览器内存 | 不随每次交互写入数据库 |
| 分析记录 | 既有 `experiment_records` | 新建/修改/删除仅教师/管理员；历史学生记录保留 |

旧版 `experiment_reference_sets.data_json.sheets` 仍保留兼容读取；新上传参考文件不再把整张表的单元格内容存入 JSONB。

## 3. 性能策略

1. 学生登录和首页不加载完整实验计算引擎、图表库、PDF 编辑库或在线 Excel 运行时。教师打开对应功能时才按需加载资源。
2. 学生模板按需单份读取；班级任务列表不读取所有工作簿快照。
3. 教师批阅列表每次最多读取 100 条记录，并缓存已获取的学生姓名信息。
4. 报告和参考工作簿放入私有对象存储，数据库保存必要的业务元数据；模板只有显式保存才更新。
5. 教师数据分析在浏览器本地运行，拟合与图表刷新不逐次调用数据库或服务器函数。

## 4. 权限与兼容

- `assignment_templates` 的 RLS 允许管理员/负责教师管理；学生只可读取其有效班级中已开放任务的模板。
- 教师参考工作簿 Storage 目录仅允许对应班级教师和管理员读写；策略显式使用 `objects.name` 解析班级目录，避免与班级表的 `name` 字段混淆。
- 学生端旧分析记录写入策略已收紧；历史记录不会被删除。
- 既有报告、提交版本、原始 PDF、批阅版 PDF、批注与报告修订记录均保留。

## 5. 30,000 次交互目标与验收边界

本版本已进行减少数据库读写与文件传输的架构调整，但 30,000 次交互尚未通过真实并发压测，不能把目标写成已验证容量。正式确认前，应使用合成账号和测试数据执行至少 30,000 次交互/并发测试，并观察 Supabase Database、Storage、Auth、网络出站流量、RLS 查询与 GitHub Pages CDN 指标。不能用浏览器本地单机点击代替并发测试。

还应使用真实 Microsoft Excel 与 WPS 完成中文界面、公式、日期/数字格式、多工作表和文件往返验收，并使用学生、教师、管理员账号分别验证权限。

## 6. 在线表格依赖

在线工作簿编辑器采用 Univer 1.4.0 UMD 组件，按需加载并使用简体中文资源；Excel 文件导入/导出由独立文件组件负责。若学校/网络环境限制公共 CDN，需将依赖文件托管到自有静态资源域名。
