# 账号重置、邮件回跳与性能说明

## 1. 密码重置流程

1. 管理员或获授权教师发起重置，平台向目标账号邮箱发送 Supabase Auth 密码重置邮件。
2. 邮箱链接只用于确认本次重置请求，不作为日常登录方式。
3. 用户点击有效链接返回 TJUCPE 后，Supabase Auth 建立密码恢复会话；此链接只证明用户能够访问该邮箱。
4. 用户直接在网页输入并保存个人新密码（至少 10 位），平台不向邮箱发送明文密码，也不设置所有人共用的默认密码。
5. 保存成功后清除 `must_change_password` 标记并进入平台。若链接过期或已使用，重新发送一封恢复邮件即可。

## 2. Supabase 邮件跳转配置（必须核对）

GitHub Pages 项目地址：

`https://untholionleen.github.io/TJUCPE/`

在 Supabase Dashboard → Authentication → URL Configuration 中：

- Site URL：设置为上述 TJUCPE 项目地址。
- Redirect URLs：添加上述完整地址（包含末尾的斜杠）。
- 如果此前配置过其他部署域名，请确认当前邮件模板和允许跳转列表没有指向旧站点。
- Password Recovery 邮件模板应保留 Supabase 提供的确认链接变量（通常为 `{{ .ConfirmationURL }}`），不要将链接手动改成一个普通网页地址。

如果点击邮件后出现无效链接、回到旧域名、没有进入“设置新密码”页面，优先检查 URL Configuration、邮件模板和链接是否已过期/使用过。重置链接通常只能使用一次。

## 3. 管理员入口与身份权限

- “用户与权限”仅向 `admin` 身份开放；教师和学生不会看到该入口。
- 管理员可以邀请学生/教师、调整学生/教师/管理员身份、停用/恢复账号、发送单人或批量重置邮件。
- 教师仅能管理自己负责班级中的学生；不能自行授予管理员身份。
- 当前数据库存在一个启用中的管理员身份。若登录后看不到“用户与权限”，请确认当前登录账号是否就是该管理员账号，而不是教师或学生账号。

## 4. 班级任务数据导出

教师在“班级与任务”中对某次任务点击“导出本次班级数据”，ZIP 包含：

- 全班成员的提交状态（包括未提交成员）；
- 该次任务的报告汇总 CSV、当前报告文件；
- 明确绑定该任务的学生数据处理记录；
- 中文字段索引、原始数据与分析结果 JSON。

从普通实验目录进入的独立分析记录不会自动猜测归入某个任务。学生应从任务卡片点击“开始实验”，再保存数据分析记录，记录才会绑定到本次任务。旧记录不会按创建时间粗略匹配，避免把其他任务的数据误导出。

## 5. 首屏与移动端性能

XLSX、ZIP、DOCX 预览组件按需加载；Plotly 在首次运行专属计算/Origin 式选区拟合时加载。这样可以减少手机首屏需要下载的脚本体积，同时保留矩形框选、套索选点和重新拟合功能。

Supabase 后端响应还受网络、浏览器代理、邮件服务和项目运行状态影响。遇到长时间无响应时，先查看页面中文错误提示，再检查 Supabase Logs；不要连续重复点击提交、重置或删除按钮。
