# TJUCPE v2.4.1：创建班级与管理员入口修复

## 本次修复
- 为“创建班级”增加独立的全局按钮桥接入口；原生 click 事件与表单 submit 仍保留，避免因单一事件监听未建立而完全无响应。
- 点击后立即更新页面状态为“已接收操作”；提交期间按钮锁定，防止重复写入。
- Edge Function 返回的原始错误、状态码与中文说明会同时显示，不再只显示笼统的“操作未完成”。
- 对未捕获的浏览器脚本错误和异步 Promise 异常增加可见提示。
- 任务发布加入处理中状态、重复提交保护及统一失败提示。
- 非管理员账号尝试进入“用户与权限”或“系统管理”时，明确提示当前角色和管理员账号登录要求。
- 更新 app.js、styles.css 的版本查询参数及页面显示版本，强制浏览器加载新资源。

## 权限核验结论
- profiles.role 是权限判断依据。教师可以创建由本人负责的班级；管理员可以创建班级并指定有效的教师负责人。
- users / system 页面只允许 admin 角色进入。教师页面不显示这两个入口是权限隔离，不是功能文件缺失。
- 线上当前有 1 个 active admin、1 个 active teacher、1 个 active student；教师和管理员的 Auth app_metadata.role 均与 profiles.role 一致。
- 线上班级数为 0，因此班级名单、班级任务、Excel 模板任务选择、班级参考数据下拉框在首个班级建立前为空。创建班级后这些入口才有实际目标。
- 本次不创建测试班级、不清空数据、不修改学生报告或文件。

## 发布后验证边界
- 已对照线上 Supabase 请求日志，截图对应教师会话在加载班级列表后没有发出 create_class 请求；本次改动针对请求发出前的前端入口和反馈链路。
- GitHub Actions 自动化测试可验证代码结构与构建；真实登录态下的最终端到端创建仍需用平台账户在浏览器完成。不得把 CI 通过等同于真实账号创建成功。
