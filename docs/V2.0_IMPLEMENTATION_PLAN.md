# TJUCPE 2.0 — 重构实施说明（第一批）

> 基线：TJUCPE 1.0（main）；本分支仅承载 2.0 第一批改动，尚未合并 main。
> 原则：保留原有三端、任务、报告版本、私有文件、RLS 与已验收计算工作流；先完成教师主导的数据工作流，再开展逐实验算法校核。

## 1. 2.0 产品目标

2.0 的核心转变是：**学生独立完成数据处理文件和实验报告；教师在教师端统一查看学生数据、生成教师参考图、对照数据与图表、给出有证据的反馈。** 平台不再把学生端自动计算结果作为报告结论的替代品。

### 1.1 学生端

1. 查看教师发布的实验任务及对应模板版本。
2. 下载该实验的 Excel 数据处理模板（一个工作簿可包含多个命名工作表、字段说明、单位、数据录入区、原始数据区；不得把教师参考数据写入学生模板）。
3. 学生独立完成 Excel 数据处理、公式、计算、绘图与分析。
4. 同一任务提交一份 Excel 工作簿 + 一份报告文件。报告允许 PDF；DOC/DOCX 需经服务端 MIME/文件签名验证后开放，不能仅凭扩展名接受。
5. 提交后显示每个文件的状态、版本号、提交时间和教师反馈；补交产生新版本，原始文件保留。
6. 学生端不展示教师参考数据、参考图、参考答案或其他学生数据。

### 1.2 教师端

1. **实验模板工作室**：建立/编辑模板版本，设置工作表、字段名、单位、说明、必填列、数据类型、允许误差、导入映射和模板下载文件。
2. **教师参考数据工作室**：上传教师参考 Excel/CSV，填写数据来源、实验条件、温度/浓度/仪器参数、版本、审核人；按实验与模板版本关联。
3. **教师参考成图**：教师选择参考数据集和绘图配置，生成散点图、整体线性拟合/指定物理模型、残差与统计量。参考数据与参考图仅授权教师和管理员可见。
4. **学生提交审阅**：同屏展示学生 Excel 工作簿（工作表/原始数据/公式结果/图表）、报告 PDF/DOCX、教师参考数据与参考图；标出字段缺失、单位不符、数据点数异常、拟合参数偏差及图表要素差异。
5. **反馈批注**：按工作表、数据区域、图表、报告页建立批注；教师可引用学生具体单元格/行号和参考值，反馈应说明问题，不自动改写学生数据。
6. **PDF 编辑器**：保留现有画笔/圈画工具，增加文本插入；文本与笔迹嵌入新 PDF 文件，作为新版本上传，更新报告当前版本路径，保留旧版本。
7. **成绩与流程**：保留现有分项评分、评语、退回补正、成绩确认和审计日志。

### 1.3 管理员端

1. 管理实验模板、模板版本、教师参考数据权限和系统策略。
2. 可跨班级查询教师工作流和提交审阅状态；不默认向管理员工作台展示学生个人学习任务。
3. 管理班级、账号、实验目录、全局权限与审计日志。
4. 管理员可查看所有教师模板与参考数据的变更历史。

## 2. 任务与提交模型

每个实验任务固定引用不可变版本：
- `experiment_catalog`：实验主目录。
- `experiment_template_versions`：模板版本、字段 schema、单位、说明、模板文件路径、版本号、发布状态、创建者。
- `experiment_reference_datasets`：教师参考数据元信息、文件路径、条件、审核状态、关联模板版本。
- `experiment_reference_plots`：教师参考图配置、拟合模型、统计量、图文件路径、生成代码版本。
- `experiment_assignments`：任务必须绑定 `template_version_id`，可选绑定一个或多个已审核参考数据集（仅教师视图）。
- `report_submissions`：保留报告文件路径及成绩/评语；新增提交版本关联。
- `submission_artifacts`：一个提交版本下的多个文件，至少支持 `report` 与 `data_workbook` 两类，记录 MIME、大小、SHA-256、storage path、上传人和时间。
- `submission_feedback_items`：按 worksheet/cell-range/chart/report-page 锚定的反馈项。
- `report_revisions`：继续保留 PDF 批阅文件的版本历史。

上述为目标数据模型，不表示已经写入线上数据库。本分支不执行破坏性 SQL；先审查线上 migration history、现有约束和 RLS，再生成可回滚迁移。

## 3. 数据文件规范与导入流程

### 3.1 Excel 模板规范

- 工作簿含 `README_填写说明`、一个或多个实验数据工作表。
- 首行字段名，第二行单位/字段说明（或由单独说明页定义），数据从明确标记的首个数据行开始。
- 保留原始测量值；派生列须有公式说明、单位和公式版本；禁止模板预填参考实验数据。
- 保护字段定义行但不锁定学生数据录入区；禁止合并单元格作为数据结构。
- 每张表有稳定的内部 table key，显示名可以中文编辑；上传时以 key/字段 schema 匹配，不依赖文件名。

### 3.2 学生上传校验

1. 文件扩展名、MIME 与文件签名共同校验；XLSX 必须能解析为合法 ZIP/XML 工作簿。
2. 展示工作表清单、列名、行数和前 10 行预览。
3. 字段映射由稳定 key 和别名表识别；无法识别时让学生选择映射，不静默套用其他实验列映射。
4. 数值列逐单元格校验；空值、文本、无穷大、异常分隔符均报告工作表/行/列。
5. 先写临时对象，校验通过后创建提交版本；失败时不创建“已提交”记录、不残留空报告。
6. 同一幂等提交 ID 防止重复点击造成重复记录；前端明确显示上传进度、成功/失败、重试入口。

### 3.3 TXT/CSV 兼容

- UTF-8/UTF-8 BOM；分隔符自动检测仅用于建议，预览后由用户确认。
- 不允许把“无法解析的文本”静默变成伪造数据；错误时保留原始文件并报告准确行列。
- 每个 TXT 模板明确表头、单位、列顺序、示例空行及编码。

## 4. 拟合与制图规则

1. 第一批按用户意见取消框选/套索选区影响拟合；拟合斜率使用全部通过校验的有效数据点。
2. 图上仍可缩放、平移、查看点值，但不能通过点选改变计算数据子集。
3. 线性回归明确输出 n、斜率、截距、R²、SSE、RMSE、残差；报告单位与模型。
4. 实验专属计算必须使用经课程教师确认的公式和输入单位；多系列数据分组拟合，不得误把不同温度/浓度系列混合。
5. 异常点只标识和解释，不自动删除；如教师批准排除，记录排除点、理由、操作者和时间。
6. 教师参考图必须记录参考数据集版本、模板版本、绘图配置、拟合算法版本和生成时间。
7. 不把“R² 高”作为模型正确的充分条件；结合残差、物理机理和实验指导书判断。

## 5. PDF 编辑器范围

本分支第一批增加文字工具：教师切换“文字 T”，在 PDF 页面点击输入文字；画笔和文字都会显示在预览层并嵌入新 PDF 二进制文件。保存仍遵循：
- Blob 为不可变原始数据源；
- PDF.js 与 PDF-Lib 各自从 Blob 获取独立 ArrayBuffer；
- 新 PDF 上传到私有 Storage 新路径；
- 数据库更新当前版本路径并写入版本历史；
- 学生与教师始终读取同一个当前版本；
- 上传/数据库确认失败时不覆盖原始文件，进行状态核查和可恢复提示。

当前文字渲染使用浏览器 Canvas 将文本绘制为图像后嵌入 PDF，保证中文可见；文字不是可再次选择编辑的 PDF 文本对象。下一阶段可引入经过许可的 CJK 字体嵌入及可编辑文本注释层。此差异须在界面说明，不能宣传为完整 WPS/PDF 文本对象编辑能力。

## 6. 班级删除与强制导出

删除班级不允许直接级联删除教学数据。流程：
1. 用户发起删除，服务端锁定班级并生成数据清单。
2. 必须导出班级全量归档包：名单（按授权）、成员关系、任务、提交元数据、所有报告/Excel/批阅 PDF 版本、反馈、评分、审计记录。
3. 服务端生成 ZIP 和 manifest（文件路径、SHA-256、文件大小、记录数、导出时间），放入私有 Storage。
4. 前端提供下载，用户确认下载成功并二次确认；服务端验证归档对象存在且 manifest 完整。
5. 有历史报告时默认归档/停用班级，不做硬删除。若机构政策允许彻底删除，必须单独授权并记录审计。
6. 归档失败、下载链接失效或校验不通过时，禁止删除并显示原因。

## 7. 访问控制

- 学生仅访问自己的提交、自己的上传文件和任务绑定的学生模板。
- 教师仅访问其授权班级的学生文件、模板与参考数据。
- 参考数据 Storage 路径使用独立私有目录；RLS + Storage policies 双重约束。
- 管理员有全局查询权，但敏感操作审计。
- 不使用可由用户编辑的 `user_metadata` 决定角色；管理员任命继续走受控服务端流程。
- 前端隐藏按钮不构成权限；每个查询、写入、文件下载均须由 RLS/Storage policy 授权。

## 8. 本分支第一批改动与限制

- 增加 PDF 页面文字插入入口；文字将与画笔标注一同烘焙进新的 PDF 版本。
- 修复实验表格导入函数的异步声明，避免读取文件时因 await 语法/执行错误中断。
- 取消 Plotly 框选/套索作为拟合区间的交互入口；拟合范围回归为全部有效点。
- 保留第一版三端和已有业务流程。

**尚未完成且不能宣称已部署：** 教师模板编制/版本管理 UI、参考数据工作室、双文件提交与归档模型、学生工作簿在线解析预览、教师数据与图表对照工作台、班级强制导出归档服务端流程。上述需要下一批前后端与数据库迁移开发，并完成 RLS/Storage/端到端测试。

## 9. 发布门槛

1. JS 语法与静态检查通过。
2. TXT/CSV/XLSX 模板下载→填入→上传→预览→提交端到端测试通过。
3. 中文文字/画笔批注保存后重新下载、重新打开，文字和笔迹均可见。
4. 报告版本、学生当前版与教师当前版路径一致；失败注入不覆盖原文件。
5. 学生不能读取参考数据或他人文件；跨班教师不能越权。
6. 班级删除前无归档 ZIP / manifest 时必须拒绝。
7. 全部测试在 staging 账号和合成数据中完成后，才允许合并 main 并发布。
